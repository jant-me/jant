## 丢数据

- [x] 1 SQLite 备份漏掉最近的写入、恢复可能损坏（已复现）：`jant start` 不处理 SIGTERM，Docker 里 node 是 PID 1，
      `docker compose down` 10 秒后强杀，WAL 没写回主库；`backups.md` 只打包、只删 `jant.sqlite`。
      做法：`start` 收到 SIGTERM/SIGINT 时关闭 HTTP 服务和数据库；备份带上 `jant.sqlite-wal`，恢复先删
      `jant.sqlite`、`-wal`、`-shm`（中英）
- [x] 2 编辑已发布的帖子时移除已有附件，前端立刻 `DELETE /api/media/{id}`（`client/compose-bridge.ts:533`），
      放弃编辑也回不来。做法：已有附件移除时不发请求；保存时由服务端删掉这次被移除的媒体
- [x] 3 建帖/改帖时带上别的帖子的媒体 ID，附件被悄悄挪走，删新帖连文件一起删（已复现）。做法：媒体已属于别的帖子
      时答 `409`，HTTP 与 MCP 同一处校验；`API.md` 写明删帖会删附件文件
      顺带发现（已复现）：重新保存或发布带附件的帖子串草稿时，路由先删旧草稿连同附件文件，再用同样的媒体 ID 建新帖，
      答 400，草稿和图片都没了。改为 `posts.replaceThreadDraft()`：先解绑旧草稿的附件，建好新帖子串后只删去掉的；
      帖子串建到一半失败时，回滚只解绑上传的文件、不删
