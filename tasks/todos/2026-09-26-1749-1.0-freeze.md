# 1.0 冻结准备

1.0 之后，下面这些面上的破坏性改动都要等 2.0。趁现在删改还不算破坏，把要冻结的东西定下来、
清理干净，再发版。

分两类：**A 类**有公认做法，我直接定；**B 类**是产品或对外决策，要和 Owen 商量。
B 类定完之前，A 类里依赖它的项不动。

## 已核实的前提

- 用户站点只用 `createApp()`：`sites/*`、create-jant 模板、`jant-starter`、`owen-jant`
  全是 `import { createApp } from "@jant/core"`。jant-cloud 不 import 这个包，只通过
  `/api/internal/sites/*` 调用 core。
- 0.7.0 之后公开 API 只有新增（`createdAt`/`updatedAt`、媒体列表 `cursor`、
  `durationSeconds`、导航链接 `description`、`redirectType` 接受数字、`/readyz` 的
  `version`），没有破坏性改动。
- `/api/upload/multipart` 在文档里叫 legacy，但 Jant 自己的客户端
  （`src/client/multipart-upload.ts`）还在用。
- Postgres 在 `docs/deployment-docker.md` 里是正式选项，但 CI 只演练 D1 的 migration。
- `@jant/core@1.0.0` 已在 npm 上（2026-04-19 误发，已 deprecate），版本号不能再用。
  远端有 `v1.0.0`、`@jant/core@1.0.0`、`create-jant@1.0.0` 三个旧 tag。
