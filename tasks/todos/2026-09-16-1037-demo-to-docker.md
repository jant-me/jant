# 把 demo.jant.me 从 Workers 搬到 Docker 自部署

## 背景：慢在哪

> **更正（同日）**：本节最初的诊断是「D1 在 APAC、请求落在 SJC，3 次跨太平洋
> 串行往返」。这是错的，下面是修正后的结论。

`/readyz` 只做一次无约束 D1 查询且绕开站点解析与 auth，用它减 `/healthz`
（完全绕开 runtime）得到**单次 D1 查询的净成本**。当时从 SJC 测得三次采样
0.2764 / 0.2767 / 0.2752s，基线 0.242s → **约 34ms**。跨太平洋往返是 130ms+，
所以 34ms 是同区副本：**read replication 是生效的**，匿名请求走
`first-unconstrained`（`runtime/index.ts:38`），路由逻辑也没问题。

真正的原因是**查询次数**，不是距离：

| 路径 | 服务端时间（SJC） | ÷ 34ms |
|---|---|---|
| 单篇文章页 (18KB) | ~430ms | ≈ 13 次查询 |
| `/` (90KB) | ~560ms | ≈ 16 次查询 |

18KB 的文章页和 90KB 的首页服务端时间接近，与 HTML 体积无关。

**这改变了搬迁的意义**：SQLite 本机查询 ~0.05ms，13 次 = 0.65ms，所以搬到 Docker
仍然能把这部分时间抹掉 —— 但那是**盖住**查询次数问题，不是修掉它。每个照
`docs/deployment.md` 部署到 Cloudflare 的用户都还在付这 ~450ms。

所以搬迁的正当理由应当写成「让 Docker 路线有一个生产实例」，而不是「让 demo 变快」。
治本的是减少文章页那条链上的串行查询（站点解析 → settings → path_registry → post →
media → nav → aliases → translations）。

**另外，smart placement 在此前提下是有害的**：副本已经在读者附近，把 Worker 挪到
主库旁边只会抵消副本的作用。

### 测量口径提醒

同日晚些时候从 **KIX**（大阪，紧邻 APAC 主库）复测，所有页面都快得多，
但这与上午的 SJC 数据**不可比** —— colo 变了，单次查询成本本身就变了。而且
`/readyz` 的中位数一度低于 `/healthz`，说明笔记本 + 代理的墙钟采样噪声很大。

要判断某次改动（例如 `79086d97 Cut the serial D1 reads a public page waits on`）
是否真的减少了往返，应当**直接计数每请求的 D1 查询次数**，而不是从笔记本推算墙钟。

## 目标形态

- Docker 容器跑 `owenyoung/jant`，SQLite 在 `/var/lib/jant/jant.sqlite`
- 媒体**继续留在 R2**（`STORAGE_DRIVER=s3` 指向 R2 的 S3 endpoint）

## 每日重建怎么改

现在（Workers）是四段拼起来的，其中三段绑死 D1：

| 现在 | 实现 | 搬到 Node 后 |
|---|---|---|
| `demo-bootstrap` | `ensureManagedSetup({ flag: "--remote" })` | 改传 `--node`，`flag` 本来就是参数 |
| `clear-storage.mjs` | `queryRemoteD1` + R2 删除 | 需要 Node 查询路径 |
| `clear-content.mjs` | `queryRemoteD1` | **删掉** —— `snapshot import --replace` 覆盖 |
| `import-canonical.mjs` | `jant site snapshot import --remote --url` | 改 `--node`，走本地 CLI 不走 HTTP |
| `clear-api-tokens.mjs` | HTTP + `INTERNAL_ADMIN_TOKEN` | 不动，与运行时无关 |
| `verify.mjs` | `queryRemoteD1` | 需要 Node 查询路径 |

关键发现：`jant site snapshot import --path <dir> --replace --node` 已经支持 Node 运行时，
`--replace` 会先 `DELETE FROM` 全部 site-scoped 内容表（`SNAPSHOT_CLEAR_TABLES`）再导入，
并保留 user/auth shell。所以 `clear-content.mjs` 整个可以删。

注意 `--replace` **不**清 `api_token`（不在 `SNAPSHOT_CLEAR_TABLES` 里），
所以 `clear-api-tokens.mjs` 仍然要留。

重建后的形状：

```
jant site snapshot import --path sites/demo-source/canonical/snapshot --replace --node
<清掉不在快照里的孤儿 R2 对象>
jant uploads cleanup --url https://demo.jant.me
node scripts/demo-public/clear-api-tokens.mjs
node scripts/demo-public/verify.mjs   # 需要 Node 查询路径
```

## 风险与取舍

- **单区域**。Cloudflare 在前面做 TLS 终结，所以远端读者付的是 1 次回源长途，
  而不是今天的 1 次 + 3 次 D1 往返。仍然比全球边缘差，但净赢。区域按 demo 真实读者分布选。
- **demo 演示的东西变了**。今天 demo 演示的是"按文档部署到 Cloudflare"的结果，
  搬完演示的是 Docker 路线。这不一定是坏事（Docker 路线目前没有任何生产实例在跑），
  但它是一个真实的语义变化，值得想清楚。
- **R2 回收窗口**。S3 driver 支持服务端 copy，所以删除走 `trash/` + 30 天回收窗口。
  每日重建会让 trash 堆 30 天。`jant uploads cleanup` 负责扫，但要确认它真的扫得动这个量。
- **这 0.4s 是所有 Cloudflare 上的 Jant 用户都在付的**，不只是 demo。把 demo 搬走等于
  绕开了这个问题而不是解决它。已决定本次不处理，**但要单开任务**：试
  `[placement] mode = "smart"`（全仓库目前没有任何 `[placement]` 配置），
  以及把站点解析→settings→post→media 这条串行链批起来。
