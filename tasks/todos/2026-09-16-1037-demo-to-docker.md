# 用 demo-node.jant.me 验证 Docker 版 demo

## 目标

在 `demo-node.jant.me` 起一个**与现有 demo 并行**的 Docker + Node 版 demo，
内容与 demo.jant.me 相同，每日自动重建。

- **现有 demo.jant.me 完全不动**。它继续跑在 Workers 上，每晚照常重置。
- 切不切换是之后的独立决定，不在本任务范围。
- **没有性能目标**。文章页的串行查询已在另一个会话里解决，Workers 版不一定更慢，
  单机版对离机器远的读者反而可能更慢。本任务的理由是让 Docker 部署路线有一个
  真实的生产实例。不要拿「变快了」当验收标准。

## 已定的设计

| 项 | 决定 |
|---|---|
| 数据库 | SQLite |
| 每日重建 | **删库重建**：清掉本站对象 → 删 SQLite → 从空库迁移 → 建 demo 账户 → 导入快照 |
| 媒体 | R2 via S3 driver，**单独建一个桶**，不与 demo.jant.me 或 hosted 共用 |
| 静态资源 | 仿照 hosted 的 `jant assets upload` + `ASSET_BASE_URL`，放在同一个桶的 `_assets/` 下 |
| 部署配置位置 | `/Users/green/project/studio/external-apps/jant-demo/`，仿照 `external-apps/jant/` |

### 为什么删库重建，而不是 `--replace`

`--replace` 是为「把内容快照恢复进一个真实站点」设计的，它保留站长的其他设置。
demo 要的是「把游乐场恢复原状」，拿前者当后者用会漂移 —— demo.jant.me 上已经发生了：

```
DASHBOARD_LANGUAGE = 'zh-Hans'   2026-08-04 起，43 次重置都没恢复
CJK_SERIF_FONT     = 'zh-Hans'   同上
DISCOVERY_*_AT     = …           2026-05-14 起，此后访客都看不到新手提示
```

demo 模式只锁 `NOINDEX` 一个设置（`src/lib/api-settings.ts` 的 `demoLockedSettingKeys`），
其余访客都能改，而 `--replace` 只恢复 `SNAPSHOT_SETTING_KEYS` 里的 19 个。

删库重建的好处：每天早上真正干净；**不依赖任何「该清什么」的手写清单**，新表和新设置
天然被清掉；存储清得更彻底（没有数据库记录的对象也会被删）；新库里本来就没有
API token 和上传会话，省掉两个清理步骤。

代价：测不到「旧库 + 新迁移」的升级路径（`migration-rehearsal.yml` 部分覆盖）；
重建期间短暂停服、访客全部登出；建 demo 账户的逻辑每晚从零跑，必须可靠。

### 为什么单独建桶

删库重建要先清掉本站在 R2 上的对象，这是按前缀批量删除。和 demo.jant.me 共用桶时，
前缀一旦取错（例如 site id 为空，`media/{siteId}/` 变成 `media/`）就会删掉线上 demo 的
全部媒体。单独建桶把这个风险整个拿掉。

## 硬约束（漏掉任何一条都会白干）

1. **清桶必须有两道护栏。** 单独建桶之后，风险从「前缀取错」变成「桶取错」——
   同一个清桶操作若因配置错误指向 `jant-demo-media` 或 `jant-cloud-media`，是灾难。
   - **R2 token 权限只限这一个桶。** 配错时请求直接被拒绝，而不是删东西。这是主护栏。
   - **重建代码里断言 `S3_BUCKET` 等于这个专用桶的名字**，不等就拒绝运行。兜底。
2. **清桶时保留 `_assets/`，删掉其余所有对象。** 不要只删 `media/` 和 `trash/`：
   枚举要删的前缀，新增前缀时会静默泄漏；枚举要留的前缀，出错时静态资源丢失，
   页面立刻坏掉，验证会抓到。选响亮的失败方式。
3. **SQLite，不用 Postgres。** 同机 hosted 在跑 PG，不要复用。canonical 快照是
   `"dialect": "sqlite"`，`assertSnapshotDialectMatches` 拒绝跨方言导入。
4. **独立的 Jant 实例，单站点。** `DEMO_MODE` 是 `envOnly: true`，实例级。
5. **仿照 hosted 但不要照抄这三处：**
   - `compose.deploy.yaml` 的 `environment` 里写死了 `SITE_RESOLUTION_MODE: host-based`
     —— demo-node 必须是单站点
   - `.env.tpl` 的 `DATABASE_URL` 指向 Postgres —— demo-node 用 `DATA_DIR` + SQLite
   - hosted 的 R2 凭据 `COMMON_CLOUDFLARE_S3_*` —— demo-node **不要用**，用只限专用桶的 token
     （约束 1）。另外那组 secret 名 `COMMON_CLOUDFLARES3_SECRET_ACCESS_KEY` 少一个下划线，
     对照 hosted 模板时别被绊到
6. **重建期间应用必须停着。** 删 SQLite 文件（含 `-wal`、`-shm`）时不能有进程开着它。
7. **不要往 `sites/demo/` 加文件。** 它是 create-jant 模板源：
   `packages/create-jant/package.json` 的 `copy-template`（`prepublishOnly` 触发）用
   `rsync -a ../../sites/demo/ template/` 整目录拷贝。
8. **demo-source 留在 Cloudflare 不动。**

## 可以复用的

### 直接复用

| 东西 | 位置 |
|---|---|
| canonical 快照 | `sites/demo-source/canonical/snapshot/` |
| Docker 镜像 | hosted 用的同一个构建（`__REPO=jant-me/jant`） |
| 部署结构 | studio `external-apps/jant/`：`.env.tpl` 契约、`compose.deploy.yaml`、`pre-deploy` profile 跑 migrate 与 assets upload、`/readyz` healthcheck、`shared` 网络 |
| 容器内 CLI | `jant migrate`、`jant site snapshot import --replace --node`（导入命令强制要求 `--replace`，空库上它等于直接导入） |
| 前缀列举 | S3 driver 实现了 `listAllKeys(prefix)`（`src/lib/storage.ts`），清桶可以用 |
| 失败上报 | `.github/workflows/report-failure.yml` |
| 快照可加载性 | `src/__tests__/snapshot-canonical-replay.test.ts` 已证明快照能导进迁移到 head 的 SQLite |

### 复用逻辑，但要抽出来

`packages/core/dev/scripts/reset-node-dev.ts`（`mise run db-node-rebuild-demo`）的流程和
删库重建几乎一样：

```
resetLocalFilesystem     删 SQLite（含 -wal/-shm）和本地媒体目录
migrate                  迁移到 head
ensureLocalDevShell      用 Node 运行时建管理员账户、完成 onboarding、种默认导航
importCanonicalSnapshot  导入快照
```

但它是 dev 取向的：写 `packages/core/.env.node`、用 dev 密码、配 `DEV_API_TOKEN`、
**只支持本地存储**。**不要复制一份改改**，把建账户和删库的逻辑抽出来让 dev 脚本和
demo-node 共用，dev 脚本行为不变。清 R2 是 demo-node 新增的一步；导入快照走 CLI，
它通过 `createStorageDriver` 支持 S3。

**唯一真正缺的生产能力是「在 Node 上建一个已知密码的 demo 账户」**
（对应 `ensureLocalDevShell`），目前没有任何生产 CLI 命令能做。

### 不能复用

| 东西 | 原因 |
|---|---|
| `scripts/demo-public/clear-storage.mjs` / `clear-content.mjs` / `verify.mjs` | 绑死 `queryRemoteD1` |
| `scripts/demo-public/clear-api-tokens.mjs` | 删库重建用不着 —— 新库里没有 token |
| `sites/demo/scripts/bootstrap-demo.mjs` 与 `ensureManagedSetup` | `flag` 直接传给 wrangler（`dev-auth-db.mjs` 的 `runWrangler([flag, ...])`），只认 `--local` / `--remote` |

## 每日重建

```
停应用
断言 S3_BUCKET 是专用桶
清桶：保留 _assets/，删除其余所有对象
删 SQLite（含 -wal、-shm）
jant migrate
建 demo 账户（DEMO_EMAIL / DEMO_PASSWORD）
jant site snapshot import --replace --node --path <快照>
起应用
验证
```

## 背景（为什么不是为了性能）

最初以为 demo 慢是「跨太平洋 D1 往返」。实测证伪：`/readyz` 减 `/healthz` ≈ 34ms，
是同区副本，read replication 生效。真正原因是文章页约 13 次串行查询，已在另一个
会话里解决。也因此**不要试 smart placement**，它会把 Worker 从副本旁边挪走。
