# 用 demo-node.jant.me 验证 Docker 版 demo

## 目标

在 `demo-node.jant.me` 起一个**与现有 demo 并行**的 Docker + Node 版 demo，
内容与 demo.jant.me 相同，每日自动重建。

- **现有 demo.jant.me 完全不动**。它继续跑在 Workers 上，每晚照常重置。
- 切不切换是之后的独立决定，不在本任务范围。
- **没有性能目标**。文章页的串行查询已在另一个会话里解决，Workers 版不一定更慢，
  单机版对离机器远的读者反而可能更慢。本任务的理由是让 Docker 部署路线有一个
  真实的生产实例 —— 那条路径目前没有任何生产实例在跑。不要拿「变快了」当验收标准。

## 硬约束（漏掉任何一条都会白干）

1. **SQLite，不用 Postgres。** 部署机器上 hosted 在跑 PG，但不要复用。canonical 快照
   `sites/demo-source/canonical/snapshot/meta.json` 是 `"dialect": "sqlite"`，
   `bin/lib/site-snapshot.js` 的 `assertSnapshotDialectMatches` 明确拒绝跨方言导入。
2. **独立的 Jant 实例，不是 hosted 里的一个站点。** `DEMO_MODE` 在
   `src/types/config.ts` 是 `envOnly: true`，实例级 —— 塞进 hosted 会给所有付费站点
   打开 demo 模式。
3. **不要共用 demo.jant.me 的 R2 桶。** 两个 demo 每晚各自清理存储，会互相删对方的对象。
4. **新文件放 `sites/demo-node/`，不要放 `sites/demo/`。** `sites/demo` 是 create-jant
   模板的源：`packages/create-jant/package.json` 的 `copy-template`（由 `prepublishOnly`
   触发）用 `rsync -a ../../sites/demo/ template/` 整目录拷贝，只排除少数几项。往里加的
   Docker 文件会漏进用户的 starter。
5. **demo-source 留在 Cloudflare 不动。** 快照从它导出，方言要保持 sqlite。

## 可以复用的

### 直接复用

| 东西 | 位置 | 说明 |
|---|---|---|
| canonical 快照 | `sites/demo-source/canonical/snapshot/` | 两个 demo 导同一份 |
| Docker 镜像 | `owenyoung/jant` | 已发布 |
| compose 结构 | 仓库根 `compose.yml` | 已有 `jant-migrate` + `jant` 两个服务和 healthcheck，照着写 |
| 容器内 CLI | 镜像 `CMD ["node", "bin/jant.js", "start"]` | `jant migrate`、`jant site snapshot import --node` 在容器里就能跑，快照挂载进去即可 |
| demo 配置 | `DEMO_MODE` / `DEMO_EMAIL` / `DEMO_PASSWORD` | 原样进 `.env`，值见 `sites/demo/wrangler.toml` |
| 失败上报 | `.github/workflows/report-failure.yml` | 新的重建 workflow 直接 `uses:` |
| 快照可加载性 | `src/__tests__/snapshot-canonical-replay.test.ts` | CI 已经用 better-sqlite3 证明快照能导进迁移到 head 的 SQLite —— 可行性的数据库那一半已被覆盖 |

### 复用逻辑，但要从 dev 脚本里搬出来

`packages/core/dev/scripts/reset-node-dev.ts`（`mise run db-node-rebuild-demo`）
**几乎就是 demo-node 的整个每日重建**，而且已经写好、跑过：

```
resetLocalFilesystem   删 SQLite 文件（含 -wal/-shm）和媒体目录
migrate                迁移到 head
ensureLocalDevShell    用 Node 运行时建管理员账户、完成 onboarding、种默认导航
importCanonicalSnapshot 导入 canonical 快照（含媒体对象）
```

它自己注明「只支持 SQLite + 本地文件存储」—— 正好是测试阶段的组合。

但它是 dev 取向的：写 `packages/core/.env.node`、用 dev 密码、配 `DEV_API_TOKEN`、
打印 auto-login、依赖仓库 checkout。**不要复制一份改改**，把可复用的部分抽出来，
让 dev 脚本和 demo-node 共用。

**唯一真正缺的生产能力是「在 Node 上建一个已知密码的 demo 账户」**
（对应 `ensureLocalDevShell`）。目前没有任何生产 CLI 命令能做这件事。

### 不能复用

| 东西 | 原因 |
|---|---|
| `scripts/demo-public/clear-storage.mjs` / `clear-content.mjs` / `verify.mjs` | 绑死 `queryRemoteD1` |
| `sites/demo/scripts/bootstrap-demo.mjs` 与 `ensureManagedSetup` | **它的 `flag` 是直接传给 wrangler 的**（`dev-auth-db.mjs` 里 `runWrangler([flag, ...])`），只认 `--local` / `--remote`，不支持 Node。（本文件早先版本说「改传 `--node` 即可」，是错的。） |

## 每日重建：整库删掉重来

本地 SQLite + 本地媒体，所以每晚直接**整个删掉重建**，不做增量清理：

| demo.jant.me（Workers）的步骤 | demo-node |
|---|---|
| `demo-bootstrap` | 需要 —— 建管理员 shell |
| `clear-storage` | **不需要** —— 媒体目录整个删 |
| `clear-content` | **不需要** —— 数据库整个删 |
| `import-canonical` | 需要 |
| `clear-api-tokens` | **不需要** —— 新库里本来就没有 token |
| `verify` | 需要，走 Node 路径 |

也因此**测试阶段不需要 R2 的 S3 凭据**。

## 背景（为什么不是为了性能）

最初以为 demo 慢是因为「D1 在 APAC、请求落在 SJC，跨太平洋往返」。实测证伪：
`/readyz`（一次无约束 D1 查询）减 `/healthz` ≈ 34ms，是同区副本，read replication
是生效的。真正原因是文章页约 13 次串行查询 —— 那部分已在另一个会话里解决。

也因此：**不要试 smart placement**，它会把 Worker 从副本旁边挪走。
