# Branch previews as a plain single-site Jant

Goal: `mise run preview-site` deploys the pushed current branch as a plain
single-site Jant on the preview VPS, at `https://jant-site-<branch>.forpreview.com`,
in about five minutes, with an owner account that can sign in.

## How a dispatch reaches the server (verified)

- `deploy-studio.yml` posts `deploy-external-app` to `tonormal/build` with
  `{service, source_ref, source_sha}`. No `studio_sha`/`deploy_ref`, so the build
  checks studio out at **main**: the studio app has to be on studio main first.
- The build derives the environment from `source_ref`: `main` → prod, anything
  else → preview with `CTX_SUBDOMAIN_SUFFIX=-<clean branch>` (`preview` itself gets
  no suffix). Clean = non `[a-zA-Z0-9-]` → `-`, lowercased, first 30 chars.
- `SOURCE_SHA` is honoured for every app whose `__REPO` is `jant-me/jant`, and
  `JANT_BUILD_ID` is baked in, so `/readyz` reports `<version>-<sha16>`. A SHA
  that fails to fetch falls back to jant main silently (no `source_repository`
  in the payload), so the task checks the served build against the SHA.
- Routes: `PUBLIC_URL` → `DEPLOY_ROUTES.txt` → a Caddy host block on preview.
  The `*.forpreview.com` catch-all (hosted jant) answers until it exists.
- A studio main push relays a prod deploy of every changed app: jant-site prod
  must render (literal placeholder secrets) and skip (`DEPLOY_ENABLED=false`).
- psenv: an empty raw value must exist in Parameter Store; a literal can be
  overridden by Parameter Store; `${X:-}` renders empty.
- Cleanup already exists in studio: `mise run preview-delete <branch> jant-site`.
