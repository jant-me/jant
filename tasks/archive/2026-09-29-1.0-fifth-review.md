## 修

- [x] S1 Release workflow 会跑 fork PR 的代码：`workflow_run` 的 `branches: [main]` 比对头分支名，fork 的 `main` 也符合；
      `9c9eb03e` 起检出 `workflow_run.head_sha`，在带 `id-token: write` 的 job 里执行。仓库至今没有 fork PR，概率低；
      修法三个条件，出事就是所有站点跑别人的代码。做法：release job 的 `if` 加 `workflow_run.event == 'push'`、
      `head_repository.full_name == github.repository`、`head_branch == 'main'`（`6c5fe2d1`）
- [x] R1 第四轮回归：编辑帖子时删掉唯一的附件，保存后附件还在（`client/compose-bridge.ts` 数组为空时不发 `attachments`）。
      做法：编辑时总是发送 `attachments`，含 `[]`。连带：恢复中断的编辑原来不带图片、文本附件丢了 `mediaId`，总是发送后保存会删掉它们，
      所以本地副本记下文本附件的 `mediaId` 和原始版本，恢复时一并放回（`ad954ae9`、`299a13f4`）
- [x] W4 打开草稿不改动、按 Escape，弹出「存为草稿？」，选「不保存」会删掉整篇草稿和文件。做法：离开编辑器（关闭、去草稿列表）时，
      已存草稿和编辑一样只在有改动时才问；「不保存」只丢弃这次的改动，删除草稿只在草稿列表里做。连带：改动判断原来只看第一个编辑器，
      帖子串草稿改了后面的帖子会不问就关，快照改为覆盖帖子串的每一篇（`3e3044f7`）
- [x] F1 feed 不输出 `feed-reading.md` 写的 `<category>`：所有 feed 共用的 `buildFeedPostViews` 不读合集。做法：读上合集（Owen），
      `jant:page` 用合集页面实际的地址（第一个自定义 URL，否则 slug），带路径前缀（`a9e7a807`）

## 不做（需要失败、少见配置或第二台设备才会碰到；都不在承诺面上，碰到再修）

- 重新保存帖子串草稿先删后建：新建失败、或另一台设备已发布后这边保存过期页面，会丢内容
- 已存草稿的编辑没有本地副本
- 打开编辑时文本附件内容没取到（空壳），保存时算作删除；R1 之前旁边有别的附件时也是这样
- `SITE_PATH_PREFIX` 加旧写法 `?hasMedia=1` 的归档链接 404；旧 feed 地址答 308，Python 3.10 及更早的 feedparser 不跟
- 合集 feed 的 `alternate` 指向首页
- `jant deploy` 不检查 `[vars]` 里被拒绝的值；`keep_vars` 下删掉的变量仍留在 Worker 上
- export → import 换主机不保留 `<jant:id>` 和媒体 ID
