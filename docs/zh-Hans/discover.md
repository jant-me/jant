# 发现

「发现」是一份公开的 Jant 博客列表，地址是 [jant.me/discover](https://jant.me/discover)。每个博客在上面同时只显示一篇文章，点进去回到博客本身。没有关注数，没有排名，没有热榜——只是大家最近写了什么，新的在前。

你的站点默认参与。要改，去 **设置 → 通用 → 站点可见性**。

## 三种取值

| 取值       | 含义                             |
| ---------- | -------------------------------- |
| `latest`   | 可以展示你的任意公开文章，默认值 |
| `featured` | 只展示你标为「精选」的文章       |
| `off`      | 不收录你的站点                   |

有两种情况会自动落到 `off`，不需要你选：

- 设了 `NOINDEX=true`、又从未动过发现开关的站点——不想被搜索引擎收录，却出现在公开目录里，这两件事互相矛盾，按更安静的那个理解更稳妥；
- 设了 `RSS_FEEDS_ENABLED=false` 的站点，因为发现读的是你的 Atom 订阅源，而这时候没有可读的内容。

演示站点永远不会被收录。

显式选择优先。你一旦用过这个开关，`NOINDEX` 就不再替你决定这件事。

## 文章怎么被选中

你的博客在列表里占一个位置，每种发布语言各一个。占位的文章会轮换：

- **文章发布大约一天后才有资格出现。** 你写的东西不会立刻进入发现。
- **同一时间只展示你的一篇文章**，停留几个小时后换下一篇。这样某个下午写得多，也不会整页都是同一个博客。
- **写得比轮换快，就会有文章始终不出现。** 这是有意的：不管一周写一篇还是一天写六篇，每个博客占的位置一样多。
- **一段时间没更新，最近那篇会一直作为你的代表**，直到它有两周左右。再往后你的博客就从列表上消失，直到你再次发布。

具体的时间间隔不是承诺。它会根据社区实际的写作量调整，改了会更新这一页。

## 把文章撤下来

不需要删除。

**在出现之前**没有什么要撤：因为有延迟，发出来又反悔的文章其实从未展示过。

**在出现之后**，把它移出 latest 订阅源，下一次读取时它就会离开发现。以下任意一种都可以：

- 给文章勾上 **Hidden from Latest**；
- 把文章设为私密；
- 把文章退回草稿。

删除文章当然也管用，但那是最重的做法，通常并不是你想要的。

## 向目录报告站点

目录没法收录一个它从没听说过的自托管站点。当你第一次在启用状态下保存「站点可见性」时，Jant 会把你的订阅源地址——仅此而已——发送给目录一次。

- 只在那次保存时发送。不定时发送，不在你发布时发送，关闭状态下不发送。
- 请求内容就是订阅源的 URL。没有站点名、没有版本号、没有任何计数或标识。
- 报告过不等于会被收录。目录仍然要抓取你的订阅源，读里面的声明，由声明决定结果。

**「站点可见性」会告诉你结果如何。** 报告有没有送达目录、你的订阅源声明了什么、以及站点离下面的门槛还差多少。这些全部读自你自己的站点——目录不回答任何关于收录名单的问题，也就没什么可问的。报告没送达时，也在这一节重试，或者打开目录的表单手动提交地址。

### 什么时候够格被收录

jant.me 收录一个博客的条件是**至少三篇公开文章**，且**最早的一篇公开文章发布满七天**。这道门槛把当天新建的测试站挡在外面，不需要任何人审核，也没有什么可申请的：跨过线之后的下一次抓取就会收录你。自建的目录可以另有规则。

新报告的订阅源会在六小时内被读取。

把 `DISCOVER_PING_URL` 指向别的目录，或者留空表示不向任何目录报告：

```sh
# 不向任何目录报告。
DISCOVER_PING_URL=

# 报告给自建的目录。
DISCOVER_PING_URL=https://directory.example/api/discover/ping
```

## 订阅源里的声明

你站点发出的每一份 Atom 订阅源，头部都带着发现设置，所以目录拿到其中任意一份都能读到你的答案，不需要另外问。

```xml
<feed xmlns="http://www.w3.org/2005/Atom" xmlns:jant="https://jant.me/ns" xml:lang="zh-Hans">
  <title>某个博客</title>
  <link href="https://example.com/" rel="alternate"/>
  <link href="https://example.com/latest/feed" rel="self"/>
  <jant:discover feed="https://example.com/latest/feed">latest</jant:discover>
</feed>
```

目录应当遵守的规则：

- 命名空间是 `https://jant.me/ns`。它是固定标识符，不是用来抓取的地址，绑定的前缀名可以任意。
- 元素文本是 `latest`、`featured` 或 `none`，其他值应当忽略。
- `feed` 属性是要抓取的绝对 URL，只在 `latest` 和 `featured` 时出现。只有当它与声明它的订阅源同源时才采纳，否则一个站点就能把别人的文章挂在自己名下。
- **元素缺失不等于 `none`。** 那说明站点跑的是发现功能之前的 Jant 版本，和明确拒绝是两回事。
- **但也不等于永久同意。** 站点必须先被读到这个元素才会被收录，所以一份声明过、之后又不再声明的订阅源不可能是旧版本——它要么降级了，要么订阅源模板坏了，要么域名易主、现在是别人在应答。元素长期缺失的订阅源应当停止收录；jant.me 的期限是三十天，之后任何一次重新读到声明都会恢复收录。
- `none` 表示停止，而且是立即停止。

多语言站点每种语言各有一份订阅源，按语言过滤，并用 `xml:lang` 标注。每一份都会列出其他几份：

```xml
<link href="https://example.com/latest/feed" rel="alternate" type="application/atom+xml" hreflang="zh-Hans"/>
<link href="https://example.com/en/latest/feed" rel="alternate" type="application/atom+xml" hreflang="en"/>
```

目录就是靠这个，从手上任意一份订阅源找到双语博客的另一种语言。单语言站点不会输出这些链接。

## 两个需要知道的地方

**订阅源有一分钟缓存。** 改了这个设置，要等下一次未命中缓存的请求才生效，所以保存后的一分钟内，目录可能仍按旧答案处理。

**改文章的 slug 会改变它在订阅源里的身份。** 发现通过 Atom `<id>` 识别文章，而 `<id>` 由地址生成。改了 slug，目录会把旧文章读作已移除、新文章读作刚发布——所以被改名的文章可能会再轮到一次。自定义 URL 是稳定的：一篇文章拿到的第一个自定义 URL 会永久作为它的身份。
